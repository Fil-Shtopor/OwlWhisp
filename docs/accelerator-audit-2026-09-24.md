# Проверка акселераторов и длинной диктовки — 24 сентября 2026

## Машина и способ проверки

- Windows x64; Intel Core i9-13900HX; Intel UHD Graphics (`PCI\VEN_8086&DEV_A788`), драйвер `32.0.101.7088`.
- NVIDIA GeForce RTX 4080 Laptop GPU (`PCI\VEN_10DE&DEV_27E0`), 12 ГиБ; драйвер NVIDIA `616.92`.
- `lw diagnose --json`: CPU — 1 устройство, CUDA — 1, WebGPU — 2; QNN, OpenVINO, Vitis AI, TensorRT, DirectML и CoreML не имеют готового провайдера/устройства в этой сборке.
- Parakeet TDT 0.6B v3, 12 реальных WAV на английском, русском, испанском и украинском, одинаковых для каждого пути. «Тёплый RTF» исключает первый фрагмент; меньше лучше. CPU использует INT8-энкодер из базовой установки. GPU использует дополнительный обычный ONNX-энкодер из того же закреплённого экспорта.

| Путь | Тёплый RTF | WER | Вывод |
|---|---:|---:|---|
| CPU, INT8 | 0,190 (0,1879 / 0,1922 в двух полных прогонах) | 0,030 | Готов без дополнительной загрузки |
| NVIDIA RTX 4080, CUDA, обычный ONNX | **0,0244** | 0,054 | Самый быстрый проверенный путь, примерно в 7,8 раза быстрее CPU |
| NVIDIA RTX 4080, WebGPU, обычный ONNX | 0,0426 | 0,054 | Примерно в 4,5 раза быстрее CPU, но медленнее CUDA |

Первоначальный вывод «лучше CPU» был **ошибочным**. В базовой установке имелся только `encoder-model.int8.onnx`, предназначенный для CPU. Прогон CUDA на этом файле дал 742 операции копирования между CPU и GPU и на 12 фрагментах практически сравнялся с CPU: тёплый RTF 0,1957 / 0,1955 против 0,1879 / 0,1922. Прежний результат по трём коротким фрагментам нельзя было обобщать. После добавления `encoder-model.onnx` с внешними данными (`2,48 ГБ`) у CUDA осталось две операции копирования, а её тёплый RTF упал до 0,0244. Эти файлы доступны у [автора закреплённого ONNX-экспорта](https://huggingface.co/istupakov/parakeet-tdt-0.6b-v3-onnx/tree/8f23f0c03c8761650bdb5b40aaf3e40d2c15f1ce).

При первой попытке обычного ONNX-энкодера CUDA выдала `cudnn64_9.dll` not found при первой свёртке, хотя все cuDNN DLL уже находились в частной папке `runtime/win-x64`. Исправлена загрузка этих библиотек из абсолютного пути приложения; после этого распознавание прошло на CUDA. [ONNX Runtime требует совместимую cuDNN 9 для этого CUDA-провайдера](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html). Это была ошибка загрузки зависимостей OwlWhisp, а не нехватка видеопамяти или отсутствие NVIDIA-драйвера.

Для этой модели на данной машине теперь рекомендуется **CUDA с дополнительным GPU-энкодером**. Разница WER в коротком тесте — 5 ошибок на CPU и 9 на GPU из 167 слов; выборку нужно расширить перед выводом о качестве. Время первой загрузки модели в эти RTF не входит. Другие модели в текущей сборке используют CPU-движок и GPU-выбор для них недоступен.

## Драйверы и установка

Системный NVIDIA драйвер и Intel графический драйвер уже установлены; CUDA и WebGPU успешно запустили модель. Поиск Windows Update (`IsInstalled=0 and Type='Driver' and IsHidden=0`) предложил только `Lenovo System Driver Update (26.8.0.29)` для `root\udsudcdriver`, без обновлений для двух GPU. Поэтому подходящих системных драйверов для скачивания на этой машине сейчас нет; никакие системные драйверы не заменялись. Необходимый здесь дополнительный файл — **энкодер модели**, не драйвер.

В настройках отдельно показываются оборудование, провайдер приложения и пригодность устройства. Если GPU обнаружен и провайдер присутствует, но устройство не запускается, кнопка **Install driver** ищет в Windows Update драйвер именно по PCI vendor/device ID, загружает и устанавливает его, затем повторяет диагностику. Если Windows Update ничего не предлагает, сообщает об этом. Путь установки нельзя было проверить на этой машине до конца без намеренной замены работающего драйвера. При необходимости Windows может потребовать права администратора или перезагрузку.

В списке выбора остаются готовые или потенциально исправимые установкой системного драйвера пути; недостающие провайдеры видны в таблице статуса, но не предлагаются как рабочий выбор. Ранее сохранённый выбор сохраняется видимым, чтобы пользователь мог его исправить.

Для установленного Parakeet при обнаруженном GPU настройки предлагают **Add GPU model**: кнопка скачивает два файла из закреплённого экспорта, сверяет размер и SHA-256, проверяет реальный запуск выбранного провайдера и сохраняет его как активный. CPU-файлы остаются на месте. Таблица различает наличие провайдера и готовность файлов выбранной модели; после полного сравнения в Benchmark сохраняет тёплый RTF для каждого ускорителя. Автоматический режим по-прежнему использует аппаратный порядок, поэтому действие выбирает конкретный проверенный GPU. Одна кнопка на этой машине не скачивает драйвер, поскольку работающий драйвер уже есть.

Отсутствие `onnxruntime_providers_tensorrt.dll`, `onnxruntime_providers_dml.dll` или OpenVINO/Vitis AI провайдера — проблема состава OwlWhisp, а не системного драйвера. В этом случае интерфейс не обещает «установить драйвер в один клик». Для этих путей ещё нужны совместимые библиотеки провайдера, а для NPU — поддерживаемый модельный артефакт. Windows x64 пакет уже собирается с CUDA и WebGPU; Windows ARM64 — с QNN и WebGPU. Подтверждение полной установки опциональных провайдеров остаётся отдельной работой. См. [документацию ONNX Runtime по провайдерам](https://onnxruntime.ai/docs/execution-providers/) и [Windows Update Agent](https://learn.microsoft.com/en-us/windows/win32/wua_sdk/searching--downloading--and-installing-updates).

Для будущего полноценного «один клик» на всех поддерживаемых Windows NPU/GPU у Microsoft есть [Windows ML ExecutionProviderCatalog](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/supported-execution-providers): он умеет получать совместимые провайдеры по требованию. Это потребует интеграции с Windows ML runtime и проверки моделей на соответствующих устройствах; каталог не подключается автоматически к текущему отдельному `onnxruntime.dll` OwlWhisp.

## Проверка определения оборудования

- Ранее зависимость от списка устройств ONNX Runtime скрывала физический GPU, когда его провайдер отсутствовал. На Windows теперь используются `EnumDisplayDevicesW` и PCI ID; на Linux — `/sys/class/drm/card*/device/vendor`. На текущей машине новый Windows детектор нашёл оба GPU с правильными PCI ID и убрал повторные записи одного адаптера.
- Ранее любой Intel CPU ошибочно помечал OpenVINO NPU как подходящий. Обычный Core i9 больше не считается NPU. Для Intel Core Ultra и обнаруженного Intel NPU остаётся кандидат; реальную пригодность по-прежнему подтверждает провайдер и запуск модели.
- Qualcomm NPU определяется по процессору и драйверу в Windows ARM64; AMD Ryzen AI — по имени платформы. Эти платформы физически недоступны на этой машине, поэтому их драйверы и одношаговая установка здесь не проверены. macOS также не проверялась на этом Windows-хосте.

## Длинная диктовка

Причина потери начала была в буфере `16_000 × 120` сэмплов. Реальный микрофон проверен: его частота **48 кГц**, и старый буфер держал лишь **40 секунд**, после чего старые сэмплы затирались. Это ограничение захвата, а не контекста модели. Теперь буфер рассчитывается по фактической частоте устройства (проверено открытием микрофона), длинная запись автоматически заканчивается через пять минут до вытеснения начала, а VAD читает только новые сэмплы и не обрывает непрерывную речь на прежней отметке 20 секунд. Parakeet обрабатывает длинный звук частями по 20 секунд также на CPU/GPU, чтобы не строить одну чрезмерно большую модельную сессию. Очистка через LLM отдельно пропускает текст свыше 8000 символов без усечения; к потере начала она отношения не имела.

Проверка длинного прохода: три разных речевых фрагмента были повторены трижды в одном файле **64,26 с**. CPU, CUDA и WebGPU распознали все три повтора, включая первый и последний. На базовом INT8-файле измеренное время распознавания: 5,018 с CPU, 4,990 с CUDA, 7,345 с WebGPU. После установки обычного GPU-энкодера тот же длинный файл обработан за **0,976 с на CUDA** и **1,863 с на WebGPU**; все три повтора остались в тексте. Время загрузки модели исключено. Это проверяет разбиение модели; пять минут живого микрофонного захвата отдельно не воспроизводились.

Сборка GUI и CLI прошла; одношаговая установка GPU-дополнения повторно проверена через реальный код приложения на этой машине: закреплённые файлы прошли SHA-256, CUDA запустила модель и распознала тестовые фрагменты. Новый переносимый x64 пакет: `dist/OwlWhisp-0.1.0-x86_64-pc-windows-msvc-gpu-preview.zip` (1,26 ГБ). Содержимое ZIP проверено: исполняемый файл, ONNX Runtime, CUDA/cuDNN, WebGPU и обновлённый манифест присутствуют. Старый выпуск `target/release/owlwhisp.exe` оставлен без замены, поскольку он уже запущен у пользователя; новая выпускная сборка сделана в отдельном каталоге. NSIS-установщик не собирался, потому что `makensis` отсутствует.

## Визуальная проверка окна

Приложение запущено на этой машине, окно снято напрямую через Win32 `PrintWindow` с учётом масштаба дисплея 150%. Проверены обычное окно Settings, таблица акселераторов, узкая раскладка, состояния CUDA/WebGPU/TensorRT/DirectML, кнопка `Add GPU model` при отсутствии дополнительных файлов и раскрытая справка CUDA со ссылкой на документацию. Снимки лежат в `.owlwhisp-test/`: `settings-window.png`, `accelerator-card-default-dpi-aware.png`, `accelerator-card-narrow.png`, `accelerator-info-install-preview.png`. Для показа отсутствующих файлов и раскрытой справки использовался временный режим debug-сборки; перед итоговой сборкой он удалён.

Проверка обнаружила дефект: событие изменения размера маленького окна оверлея подменяло ширину главного окна, поэтому Settings выбирал неверную раскладку. Теперь размер применяется только к главному окну и считывается при его открытии. В таблице закреплены ширины столбцов, а для узкого окна сохранены компактные строки. Действия кнопок через мышь в изолированной сессии Windows не воспроизводились; установочный путь дополнительно проверен программным тестом на этой машине.
